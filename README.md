# CosmosWar — модульная структура

Космическая стратегия в одном HTML-файле. Раньше вся игра (≈12000 строк:
CSS + разметка + ~10660 строк JS в одном IIFE) лежала в `CosmosWar.html`.
Теперь код разбит на **доменные модули**, которые собираются обратно в один
IIFE простым build-скриптом — поведение игры не меняется (сборка
**байт-идентична** оригиналу, проверяется `python3 tools/build.py --check`).

## Как это работает

```
CosmosWar.html  =  assets/head.html        (<head> + весь <style>)
                 + assets/body.html        (HTML-разметка: HUD, модалки, canvases)
                 + IIFE-обёртка            (    <script>\n(function() {'use strict'; )
                 + src/00..23/*.js         (тело IIFE, склеенное по порядку)
                 + IIFE-закрытие           (    })(); </script> </body> </html>)
```

**Почему именно так (concat-сборка, а не ES-модули)?** Весь JS живёт в одном
замыкании IIFE: `G`, `canvas`, `ctx`, `settings` и ~150 функций ссылаются
друг на друга по голым именам. Разбивка на файлы + склейка в исходном
порядке сохраняет это замыкание и порядок top-level деклараций (TDZ/hoisting)
— **ни одна ссылка не переписывается**. Файл остаётся самодостаточным,
работает из `file://` без сервера. Это самый безопасный путь: нулевой риск
поломать логику.

## Команды

```bash
python3 tools/split.py          # из CosmosWar.html -> src/*.js (выполняется один раз)
python3 tools/build.py          # собрать src/ + assets/ -> CosmosWar.html
python3 tools/build.py --check  # собрать и сверить с tools/CosmosWar.original.html
```

> `tools/split.py` нужен только для первичного разбиения. Обычный цикл
> редактирования — правишь `src/*.js` → `python3 tools/build.py`.

## Карта модулей — где что править

Порядок файлов **имеет значение**: `00` грузится первым, `23` — последним.
Это исходный порядок деклараций в оригинальном IIFE; его нужно соблюдать
(нельзя менять местами или в��тавлять модуль «в середину» без необходимости —
нарушится TDZ-порядок). Внутри модуля порядок свободный только в пределах
того, что не ломает hoisting (функции можно двигать; `const`/`let`/`class`
должны идти до первого использования — как и в оригинале).

## Гарантии целостности

- **Байт-идентичность.** `python3 tools/build.py --check` сравнивает собранный
  `CosmosWar.html` с эталоном `tools/CosmosWar.original.html` побайтово.
  Если расхождение — скрипт печатает символ и строку первого отличия и
  завершается с ошибкой. Запускай после каждой пересборки.
- **Покрытие тела.** `tools/split.py` имеет встроенные assert-проверки, что 24
  модуля тайлят тело IIFE без пропусков и перекрытий (тестируется при сплите).
- **JS-синтаксис.** При желании: `sed -n '1484,12153p' CosmosWar.html > t.js
  && node --check t.js` проверяет валидность IIFE.

## Как добавить новый модуль

1. Создай `src/NN-name.js` с префиксом, отражающим нужное место в порядке
   загрузки (учитывай TDZ: `const`/`let`/`class` должны идти до использования).
2. Пересобери: `python3 tools/build.py`.
3. Проверь: `python3 tools/build.py --check` (если менял только добавления
   в конце — совпадёт; если менял оригинал — обнови эталон осознанно).

## Как переименовать/переместить модуль

Просто переименуй файл, сохранив числовой префикс порядка. Имя файла — это
и порядок, и «что внутри» (см. заголовок-комментарий в каждом файле).
Порядок определяется лексической сортировкой имён, т.е. префиксом `00..23`.
